# Cross-Architecture Collider Matrix

The master matrix: every structural concept × the three architectures, with
the interface status of each. Per-concept detail lives in each file's
`[Collider]` tier; this page is the map of the whole.

**Status vocabulary:** `aligned` — the three expose mutually checkable
interfaces today · `pressure` — the interface is defined by this scaffold but
not yet executed · `open` — the interface is named but its shape is unknown.

## How to use this matrix

1. Pick a concept row. Read its structural file's `[Collider]` tier for the three interface pressures.
2. The `pressure` rows are the curriculum's lab exercises: each names an executable cross-verification (e.g. "run both skeleton functions over the same corpus and diff").
3. A row graduates from `pressure` to `aligned` only when a probe has been executed and its witness recorded — never by argument.
4. The single `open` row (error-correcting codes) is the frontier: the taxonomy is agreed, the cross-architecture detection map does not exist yet.

## Standing honesty note

This matrix is a scaffold. It defines interfaces; it does not claim integrations.
Every `pressure` is future work until a probe earns it — the same rule the
laboratory keeps everywhere else: a hypothesis stays a hypothesis until a
probe earns it.
